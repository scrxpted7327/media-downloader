# Authenticated shared media library

The media service keeps two separate lifecycles:

```text
watchMyWallet PWA
    -> private owner-scoped MediaJob
    -> completed PWA job only
    -> durable shared MediaAsset
    -> one or more MediaVariant files
```

Telegram jobs and `pool_items` never enter this promotion path. The shared
library is readable by authenticated watchMyWallet users through the private
media API and its same-origin watchMyWallet BFF. Private service credentials,
signing secrets, filesystem paths, and yt-dlp/ffmpeg arguments never reach the
browser.

## Storage and migration

Migration 9 adds `media_assets` and `media_variants`. Library files live below
`<MEDIA_BOT_STORAGE_DIR>/library/<asset_id>/`; private job retention does not
remove them. `source_key` is unique and uses a native extractor/platform ID
when yt-dlp provides one, otherwise a normalized canonical URL. Variants use
`UNIQUE(asset_id, preset_key)` so concurrent requests collapse to one row.

## Controlled presets

The initial server-side registry is:

- `video_best`: the completed PWA output/current best available file
- `video_1080p`, `video_720p`, `video_480p`: H.264/AAC MP4 generated by the
  single-worker library variant queue without upscaling
- `audio_mp3`: MP3 extracted with the reviewed ffmpeg profile
- `audio_m4a`: AAC in an M4A container, generated by the reviewed ffmpeg
  profile

The PWA can request a missing preset; the HTTP request only reserves a durable
variant row and returns. Generation happens asynchronously.

## Configuration

The existing Telegram processing limit remains `MEDIA_BOT_MAX_FILESIZE_MB`.
Shared-library policy is separate:

```text
MEDIA_BOT_LIBRARY_MAX_FILESIZE_MB=2048
MEDIA_BOT_LIBRARY_MIN_FREE_SPACE_MB=1024
MEDIA_BOT_LIBRARY_MAX_SIZE_MB=0
MEDIA_BOT_LIBRARY_VARIANT_WORKERS=1
```

`0` means no configured aggregate library cap; the free-space floor still
applies. The private media API remains loopback-bound and continues to require
the service key plus a signed ActingUserContext.

## API boundary

Private media routes include:

```text
GET  /api/media/library
GET  /api/media/library/{asset_id}
GET  /api/media/library/{asset_id}/variants
GET  /api/media/library/{asset_id}/thumbnail
POST /api/media/library/{asset_id}/variants
GET  /api/media/library/{asset_id}/stream
GET  /api/media/library/{asset_id}/download
DELETE /api/media/library/{asset_id}
DELETE /api/media/library/{asset_id}/variants/{variant_id}
```

The first six read/request routes are permission checked. Deletion requires
`media.library.manage`. Aiohttp's `FileResponse` handles byte ranges; the
watchMyWallet BFF forwards only the browser `Range` header and relays the
safe content/range headers.
